## 二、设计决策

- **核心定位**：网站此前只传递「SaaS 租户隔离 + 100% 开源 + 可自部署」，缺少官方定制开发服务这条商业化路径。本次新增「定制开发」板块，传递 **"开源是底座，定制是服务"** 的完整价值主张：
  - 开源版：免费、可自部署、可二次开发（原有叙事保留）
  - 定制开发：官方团队按需求定制，交付可用系统（可含源码），覆盖数据源对接、功能扩展、系统集成、白标、私有化、运维
- **板块位置**：放在「适用对象」之后、「FAQ」之前，id=`custom`，深色背景（section-dark）与产品功能区做视觉区隔，突出"服务"属性
- **板块结构（三层）**：
  1. **定制范围**：6 卡片 —— 数据源对接 / 功能模块扩展 / 系统集成（API/SSO）/ 品牌白标 / 私有化交付 / 长期运维升级
  2. **服务流程**：4 步 —— 需求沟通（免费评估）→ 方案报价 → 开发交付（可含源码）→ 上线护航
  3. **板块内 CTA**：邮件提交定制需求（mailto:39002818@qq.com）+ GitHub 提功能建议（开源社区共建路径，与付费定制区分）

### 发现并修复：静态资源缓存导致发版后新旧混杂

- **问题**：nginx 对 css/js 配 `expires 1h`，但文件名无指纹 → 发版后老访客最长 1 小时看到“新 HTML + 旧 CSS”，定制板块无 grid 布局、卡片重叠
- **修复**：index.html 中 css/js 引用加版本参数 `?v=20260814`（HTML 本身 no-cache，新版本号立即生效强制绕过缓存）
- **后续约定**：每次改 css/js 后，同步更新 index.html 中的 `?v=` 版本号（建议用发版日期）
